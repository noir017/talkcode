# 在聊天里改配置（`/setting`）

[English](../settings.md) | 简体中文

`/setting` 改的是 **config.yaml 本身**，所以一次改动既跨会话也跨重启 —— 这正是
它和 `/model` 的分工：`/model` 只覆盖当前这个会话，重置即失效。它替掉的是原来
那条路：登上机器、手改 YAML、重启守护进程 —— 而重启会杀掉所有常驻智能体。

| 改什么 | config.yaml 位置 | 接受的值 | 何时生效 |
|---|---|---|---|
| 默认智能体 | `routing.default` | 任一已配置的 agent id | 立即 |
| 某个智能体的默认模型 | `agents[].model`；主机 pod 声明的智能体写 `podModels` | 该智能体上报的模型、任意名字，或 `-` 清空 | 它的下一个会话（`/new` 可立刻开一个） |
| 确认子代理开跑 | `delegation.confirm` | `on`、`first`、`off`（默认 `on`） | 立即 —— 你自己直接对话的话题里，下一个 `task-new` 生效。`first` 在每个对话里对每个智能体只问一次，且只记在内存里，重启或换一个对话会重新确认；子代理的话题每次都仍要确认 |
| 空闲回收窗口 | `session.idleTimeoutMs` | `off`、`15m`、`4h` …… | 立即 |
| 会话粒度 | `session.scope` | `per_thread`、`per_channel`、`per_user`、`shared` | 重启后 |
| 流式输出 | `stream.enabled` | `on`、`off`（默认 `off`） | 立即 —— 下一条回复生效 |
| 确认语音识别结果 | `voice.confirm` | `on`、`off`（默认 `on`；仅在配了 `voice:` 时出现） | 立即 —— 下一条语音生效 |
| 整理语音识别结果 | `voice.cleanup` | `on`、`off`（默认 `on`；仅在配了 `voice:` 时出现） | 立即 —— 下一条语音生效 |
| 自动复盘 | `review.agent` | `off`，或某个 `agy` 智能体的 id | 立即 —— 下一轮扫描，一分钟内 |
| 复盘模型 | `review.model` | 复盘者上报的模型、任意名字，或 `-` 跟随复盘者自己的模型 | 立即 —— 下一次复盘 |

```
/setting                       →  整个设置面板（Web UI 是设置页，其他平台是按钮）
/setting idle                  →  这一项当前是什么、接受什么
/setting idle 4h               →  直接设，所有平台都能用
/setting model.cc opus         →  某个智能体开新会话时用的模型
```

在既能发按钮、又能改按钮的平台（Discord、Telegram、Slack、飞书），单独发
`/setting` 会弹出两级菜单 —— 点一项、点一个值，然后回到列表，新值就写在那一行
上。其余平台上同样这四条命令按文本用。模型太多会自动翻页；harness 认但没有上报过
的名字（比如 `opusplan`）会按你输入的原样保存。

Web UI 里 `/setting` 是一个设置页：话题列表底部 ⚙ 菜单里的 **All settings** 打开
它，直接输入 `/setting` 也一样。页面是一列分组 —— Agents、Default model、
Sub-agents、Conversations、Replies、Voice、Reviews —— 每一行用适合它的控件就地修改：

- **开关类**（确认子代理开跑、流式输出、两个语音开关）是开关，点一下就写入；
- **短列表**是分段按钮（空闲回收：off、15m、1h、4h、12h）或下拉框（默认智能体、
  会话粒度），选中即写入；
- **模型**每个智能体一行，行名就是智能体 id，后面是完整的模型名；没设置时灰色显示
  *harness default*。打开设置页时所在话题正在用的那个智能体标着 *this topic*。点一行
  进入该智能体的模型列表，当前模型带勾；上方的输入框边打字边筛选，列表里没有的名字点
  **Use** 直接用。

每次改动的结果显示在顶部横幅里 —— 已保存、本来就是这个值，或者被拒绝的原因；请求
没送到网关时，控件会恢复原状并提示。页面顶部写明这些设置存在 config.yaml 里、对所有
话题生效，因为没有一项只属于当前话题：要让某个话题不一样，用 `/model` 和 `/agent`。
改动默认立即生效，例外会在行上标出：模型行从该智能体的下一个会话起生效，会话粒度
标着 *after restart*。设置页不会作为消息插进聊天：你输入的 `/setting` 留在聊天里，
设置页不会。

**任何智能体的模型列表都能看，不只是当前话题在用的那个。** 列表只能从该智能体正在运行的会话里拿，
所以没有在跑的时候，网关会临时起一个会话问一下再关掉 —— 一两秒，每个智能体只问一次（定义改了才重问），
期间页面显示 *Asking … for its models*。harness 不提供模型选择、或者智能体起不来时，会分别说明，
仍然可以手输名字。

**主机 pod 声明的智能体**（`<id>@<主机>`，见[远程主机](remote-hosts.md)）也一样设置。值写进网关
config.yaml 的 `podModels`，优先于主机 pod.yaml 里的 `model:`；那一行会标明当前值来自 pod 还是在这里
设的，清掉就回到 pod 的值。会话启动时用哪个模型，从高到低：它的 `/model` → `podModels` → pod.yaml →
harness 默认。

**自动复盘**也在这里设置。`/setting review.agent ag@uniagent` 打开它，`/setting review.agent off`
关掉；这一行只列出 `agy` 智能体 —— 一次复盘就是一次 `agy -p`，所有工具都被拒绝，所以其他 harness
的 id 会被直接拒绝，而不是写进文件、等下一轮扫描时才失败。`/setting review.model` 给复盘单独指定
模型；不设就是跟随复盘者自己的模型，行上显示 *agent's own*。列表来自这个复盘者，拿不到列表时按你
输入的名字保存。这两项都在每轮扫描开始时从运行中的配置读取，所以改完一分钟内生效，不用重启。复盘者
会按 config.yaml 和各主机 pod.yaml 里实际声明的智能体核对，而不只看运行中的配置——`/reload`
失败后残留的旧行会被拒绝，不会写进一份下次启动加载不了的文件。详见
[自动复盘](skills.md#自动复盘)。

每条回执都会说清**这次改动什么时候生效**，因为它们并不一样：会话粒度只写文件、
重启后才应用 —— 在会话还开着的时候换掉「什么算一个会话」，会悄悄把所有现存会话
换成另一个身份。

文件里其余部分仍然只在文件里改，而 `/setting` 会**点名拒绝**并说明原因，而不是
装作这个键不存在。其中最值得单独说的是 `access.allowFrom`：那一项填错一次，就
把你锁在唯一能用来修它的那个界面外面了。

写入走 YAML 文档接口，所以你的注释、键顺序和 `${VAR}` 模板都原样保留；而且写盘
前会先拿整份配置校验一遍 —— `/setting` 不会给你留下一份下次重启加载不了的
config.yaml。

[定时任务](scheduled-tasks.md)也在 `/setting` 里管理。
