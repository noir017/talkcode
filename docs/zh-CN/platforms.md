Markdown 按平台分别渲染；缺失的能力平滑降级（不能编辑 → 分段发送，没有按钮 →
纯文本提问）。Slack、飞书、钉钉默认走 WebSocket 长连接，无需公网回调地址。

每个平台都是 config.yaml 里 `platforms:` 下的一项，同一类型可以出现多次来接多个账号——见
[配置](configuration.md)。网页端不是聊天服务，而是守护进程自己提供的页面，[单独一页](web-ui.md)讲。

## 平台没连上的时候

守护进程打印的 `platform instance "…" started` 只表示已经让这个平台去连接，不表示已经连上。启动一分钟后
还没有任何 bot 上线的实例会打一条警告点名它（`is not online 60s after start`），之后连上了再打一条
`is online now`。每次连接状态变化（上线、离线、重连中）也都会记进日志。

Telegram 启动时自己会重试。遇到 5xx、429、连接被拒或超时，每次失败打一行日志，写明哪个实例、什么错误、
多久后重试；从 5 秒起翻倍，最长一分钟一次，直到连上。401 或 404 表示 token 不对：只记一条错误，实例保持
离线，改好 token 后重启才会恢复。其他平台沿用各自适配器的重连行为；LINE 和企业微信启动时不重试，登录失败
就一直离线到下次重启，那条一分钟警告就是提示。
