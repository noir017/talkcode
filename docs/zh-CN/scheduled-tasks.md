# 定时任务

[English](../scheduled-tasks.md) | 简体中文

直接用大白话说——「每天早上 8 点，总结一下夜里挂掉的 CI」「30 分钟后跑一下备份，告诉我结果」——
智能体就会登记一个由网关保存的任务。智能体进程被回收、守护进程重启，任务都还在，这是各
harness 自带的定时工具做不到的。

| 类型 | 执行什么 | 结果发在哪 |
|---|---|---|
| 提示词 · **固定会话**（默认） | 在当前会话里跑一轮，由该会话的智能体回答——上下文累积，可以接着追问 | 当前会话；登记后 **24 小时**有效，之后标为已过期 |
| 提示词 · **新开会话** | 每次都是全新会话，可指定任意智能体 | 平台能不靠消息开话题的（web 界面、Telegram 论坛群）每次新开一个话题，否则发在当前聊天；不限时长 |
| 提示词 · **每日会话** | 每天一个会话：当天第一次运行开一个，之后当天的运行都进这个 | 每天一个话题，标题带日期；需要平台能不靠消息开话题（web 界面、Telegram 论坛群）；不限时长 |
| **bash** | 由网关直接执行命令，不经过智能体 | 退出码、耗时和输出末尾，输出太长会附上完整日志文件 |

结果可以发到网关回答过的任意聊天，跨平台也行（`talkcode channels` 列出这些地方）。
网关重启期间错过的运行，晚了不到一小时的会在恢复后补跑一次，更久的记为错过。每次改动都会贴
一张任务卡片，由网关写、不经智能体转述，你看到的就是实际会执行的。

每日任务按**任务自己的时区**切天，并以每次运行的**计划时间**为准：2026-11-04 当天第一次
运行开一个 `⏰ 名称 · 2026-11-04` 的话题，当天之后的运行都发进去；5 号第一次运行再开新的。
午夜之后补跑的，仍归它原定的那一天。旧话题原样保留。任务会记住当天的话题，所以中途重启网关
不会另开一个；话题被删了，下次运行就开新的——平台说不了话题还在不在时，往话题里发送失败会清掉
记录。平台开不了「不需要消息的话题」时，登记就直接拒绝；Telegram 只有论坛群能开，普通群要等
运行时才知道，那次运行算失败并说明原因，之后连续同样的失败只报一次，不会每轮刷屏。开话题失败、
或拿回来的是空话题，这次运行都算失败并在聊天里说明——不会退回去发进一个没人能回复的临时会话。

**新开会话**和**每日会话**型任务可以用 `--model <id>` 指定会话使用的模型。名字必须是该智能体
`/model` 列表里有的：不在列表里时，登记就会拒绝，报错里会列出可选项；harness 本身没有模型选择器
的也不能指定。任务开的会话从一开始就用它（每日会话是在当天那个话题开启时套用），智能体套不上时
这次运行算失败并给出原因，绝不悄悄换成别的模型。**固定会话**型任务跑在你自己的会话里，沿用那个
会话的模型（在那里用 `/model` 设置），所以对它传 `--model` 会被拒绝。每日会话的话题里，如果你
当天用 `/model` 改过，当天剩下的运行都以你的选择为准，网关重启后也一样：任务会记住这个话题被人
改过，不再套用自己的模型。

用 `talkcode schedule edit <id>` 就地修改任务：`--agent`、`--cwd`、`--model`、`--cron` /
`--at` / `--tz`、`--name`、`--prompt`，bash 任务还能改 `--bash` / `--timeout`。任务 id、运行
次数和上次结果都保留，下次运行时间按新规则从这次修改算起——改成一个今天已经过去的时刻，会等明天
而不是立刻补跑。任务「是什么」不能改：prompt ↔ bash、会话类型和输出位置（`--channel`）都会被
拒绝，想要另一个任务就 `rm` 再 `add`。每日任务改了 agent 或目录后，不能继续用当天已经开好的
话题——话题的 agent 和目录是固定的——所以下一次运行会为当天剩下的时间新开一个话题，之前那个原样
保留。

登记时用 `--tag ci,release`，之后用 `talkcode schedule edit <id> --tag …`，可以给任务打标签：
最多 5 个，每个不超过 24 个字符，会转成小写，只允许字母（中文可以）、数字和 `- _ . /`。
`edit` 整组替换，`--tag ""` 清空。标签显示在任务名下方和改动时贴出的卡片里，网页端的 Tasks
列表按它筛选。

任务的目录是某一台机器上的路径，任务必须在那台机器上跑。`--cwd` 是你敲命令那台机器上的路径，
不给时 `add` 用你当前会话的目录。所以任务要跑在另一台机器上（[远程主机](remote-hosts.md)上的
agent）时，命令会被拒绝，而不是存下一个在那里指别处的目录：给那个 agent 的 `add`、给它 `--cwd`
的修改、以及用 `--agent` 把任务挪给它却还带着旧机器目录的修改，都会被拒绝。请到那台机器上的会话
里执行（挪任务时在那里加上 `--cwd`）。没有目录的任务不受影响；bash 任务也不受影响——它跑在登记
它的 agent 所在的机器上，目录本来就来自那里。

网页端聊天标题栏右侧的时钟按钮会打开独立的 **⏰ Side tasks**（旁任务）面板：底部有 **Scheduled** 和 **Reviews** 两个标签页。在 **Scheduled** 标签页内，**Tasks** 小标签是同样的列表，另外可以「立即运行」，上方还有搜索、筛选和排序。搜索匹配任务名、提示词或命令、以及目标；**Filter** 可按 **Status**（Running、Active、Paused，以及把 expired 和 done 合在一起的 Ended）和 **Tags**（正在用的每个标签，外加 Untagged）筛选；排序有 Status（默认，沿用列表本来的顺序）、Next run、Last run、Created，可升降序，没有下次运行或从没跑过的任务两个方向都排在最后。关键词、筛选和排序都记在这个浏览器里。任务的标签在卡片里编辑：标签上的 × 删掉一个，在 **+ tag** 里输入后按回车添加一个。只有 Tasks 小标签有这个筛选条，Sessions 和 Reviews 没有。手机上是右侧滑入的抽屉，后面还看得见聊天，点变暗处就能关掉。「新会话」和「每日会话」型任务会开话题，**Sessions** 小标签列出这些话题，它们不再出现在普通话题列表里。
面板的另一个外层标签页 **Reviews** 是闲下来的对话的自动复盘（见[技能](skills.md#自动复盘)），不是定时任务；它和任务共用一个面板，只因为两者都是没有自己对话的后台工作。
`/setting` 里的 **⏰ Scheduled tasks** 按钮在所有平台都有：列出每个任务的下次和上次运行，可以暂停、恢复、
删除（删除要点两次）。没有按钮的平台，用 `/setting schedule [pause|resume|delete|run <id>]` 打字完成同样的操作。
