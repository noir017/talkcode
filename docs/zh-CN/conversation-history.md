# 以前的对话

[English](../conversation-history.md) | 简体中文

经过网关的每一轮对话都会记进一个本地库，agent 之后可以翻出别的平台、别的话题、别的
agent 里说过的事，隔几天几周都行。这是网关自己的记录，不是 harness 的：你在终端里直接
开的 Claude Code 或 OpenCode 会话不在里面。

库文件是 `<配置目录>/history.db`，网关首次启动时创建。权限 `0600`，和
`conversations.json` 放在一起，内容敏感程度与各 harness 自己的会话文件相同。

## 记什么

按所属会话逐条记：

- 一轮发给 agent 的那段话——附件只记文件名，不记内容；
- agent 的完整回复；
- 每个工具调用一行（`Bash: git status`、`Read: src/daemon/turn-runner.ts`）。

普通对话之外的事情也记，并标上类型：定时任务的一次运行（`schedule`）、子代理的话题或
`[sub-agent updates]` 汇报卡片（`subagent`）、agent 在轮次结束后才报回来的输出
（`background`）。会话的类型取它第一轮的类型；之后某一轮的类型记在那一轮自己的行上。

**写入失败绝不影响这一轮。** 磁盘满了、库打不开，网关记一条日志照常回答；回答才是要紧的，
索引不是。

## 怎么查

```bash
talkcode sessions search 跨会话查询
talkcode sessions search git status --agent cc --days 30 --limit 20
talkcode sessions read '#12' --around '#87' --window 10
talkcode sessions list --days 7
```

`search` 返回会话 id、消息 id、日期、标题、agent、平台和命中的片段。`read` 接会话 id，
从最早一条往后打印；`--around <消息>` 以某条为中心，前后各显示 `--window` 条（默认 10）。
`list` 是最近活跃的会话。

检索是关键词检索（BM25），不做向量。中文能搜到靠两点：

- **连续汉字在入库时切成两两重叠的二字词**——「跨会话查询」变成
  `跨会 会话 话查 查询`。SQLite 默认分词把整段汉字当一个词，搜不到里面的「查询」；
  它的 `trigram` 模式又搜不到两个字的词。切分在 JS 里做，入库和查询走同一套，所以
  两个字的搜索词本身就是索引里的一个词。
- **单个字退回子串匹配**，因为一个字太常见，全文命中说明不了什么。

定时任务的输出排在普通对话后面，再按相关度、时间倒序——否则一个每分钟跑一次的任务会把
用户真正要找的对话挤下去。

## 补历史

网页端从 2.13.0 起就把每个话题的记录存在磁盘上（[网页端](web-ui.md#要有的预期)）。
第一次带着库启动时，这些记录连同话题标题一起导入，历史不会从空白开始。每个文件只导入一次，
重启不会重复。Telegram、Discord、Slack 等平台上的旧对话没法从平台读回来，那些对话从开启
这个功能的那天开始记。

## 隐私

库里有每一段提问和回复的全文，包括 agent 读过的内容。敏感程度和各 harness 自己的会话文件
一样，所以权限是 `0600`，并且和配置放在同一目录。删掉 `history.db` 就删掉了整个库；网页端
的记录不受影响，之后再启动会重新导入（“只导一次”的记号也随文件一起没了）。
