# 网关自己维护的技能

[English](../skills.md) | 简体中文

自管技能由网关自己保存，并下发给每台主机上的每个智能体——Claude Code、Codex、OpenCode、Antigravity、
CodeBuddy 和 AtomCode，本机的和远程的都算。你说「把这个记成技能」，当前智能体就能写一个；其他智能体下次启动时读到它。

```text
<配置目录>/skills/                 （~/.config/talkcode/skills/）—— 一个 git 仓库
  skills/
    deploy-check/
      SKILL.md                     技能本体：frontmatter（name、description）+ 正文
      references/                  可选：技能要读的参考资料
      templates/
      scripts/
  archive/                         归档的技能，原样保留
<配置目录>/skills-usage.json       来源、创建时间、最后使用、次数、哪些智能体用过、状态、是否钉住
```

每次改动都是一次提交，技能的历史就是仓库的 log。仓库里的其他东西——README、它自己的脚本、`skills-alone/`——网关不碰，也不下发。

## 命令

`talkcode skills <动作>` 是反向命令，智能体通过自带的 `talkcode` 技能和 `talkcode help skills`
找到它。它作用于整个网关，`--channel` 不适用。

| 动作 | 做什么 |
|---|---|
| `search <需要什么>` | 最多五个合适的技能，最合适的在前——智能体就是这样找到库内技能的 |
| `show <名字> [文件] [--again]` | 看一个文件（默认 `SKILL.md`，附带这个技能的其他文件清单）和它的版本号；`patch` 必须带这个版本号 |
| `list` | 列出所有技能，含层级、状态、钉住、次数、最后使用和用过它的智能体 |
| `categories` | 技能总数，以及每个分类各有几个 |
| `create <名字> --description "什么时候用它" [--body <正文>]` | 新建技能 |
| `patch <名字> --version <版本> --content <完整 SKILL.md>` | 替换 `SKILL.md`，只接受你读到的那个版本 |
| `write-file <名字> <路径> --content <内容>` | 在 `references/`、`templates/`、`scripts/` 下增加或替换文件 |
| `remove-file <名字> <路径>` | 删掉其中一个文件 |
| `archive <名字>` / `restore <名字>` | 移进 `archive/`，或移回来 |
| `pin <名字>` / `unpin <名字>` | 让技能不参与（或重新参与）过期检查 |
| `history <名字>` | 改过这个技能的每次提交，新的在前，包括人手改的 |
| `revert <名字> <记录 id>` | 把那次提交之前的文件放回去，本身也算一次新改动 |

### 规则

- **名字**用小写单词加连字符（`a-z`、`0-9`），最长 64 个字符。`talkcode` 和 `super` 是自带的两个技能，不能重名。
- **`SKILL.md`** 最大 64 KB，必须以 `---` 开头的 frontmatter 写明名字和一句非空的用途说明。智能体的技能菜单列的就是这两项。
- **附加文件**只能放在 `references/`、`templates/`、`scripts/`，单个最大 1 MB。脚本下发后带执行权限，其余只读。
- **先读后写。** `patch` 要带上 `show` 打印的版本号；中间技能被改过就拒绝，并告诉你当前版本——重新 `show`、把改动重新套上、用新版本号再 `patch`。
  `write-file` 和 `remove-file` 不要求版本号，但每次也会产生新版本。
- **不会真删。** `archive` 只是移进 `archive/`；`revert <名字> <id>` 把那次提交之前的文件放回去，不管那次是网关提交的还是人提交的。
  两者都是提交，回滚本身也能再回滚。

## 仓库

不配置时，仓库只在配置目录下，是本地的。指向一个共享仓库后，网关会让两边保持一致：

```yaml
skills:
  repo: ssh://git@git.example:22/you/agent-skills.git
  branch: main                     # 可选，默认 main
```

- **拉取**：每 5 分钟一次，每次写入前也拉一次。所以 `patch` 总是对照最新版本检查——有人刚提交过，旧版本的修改会被拒，和别的智能体改过一样。
- **推送**：每次写入后立即推，发起修改的那一轮还在等着。作者名说明是谁写的：智能体是 `talkcode`，[自动复盘](#自动复盘)是 `talkcode-review`，
  Web UI 页面是 `talkcode-web`；提交的 trailer 里还写了智能体和会话。
- **手工修改**：和普通仓库一样提交、推送，网关 5 分钟内拿到。手写的技能不符合下面的规则就不会下发，`list` 会说明原因。
- **连不上**：写入照样在本地完成，之后再推；仓库连不上和恢复时，日志各说一次。
- **两边改了同一个文件**：以仓库为准。网关的提交留在名为 `talkcode-unpushed-<时间>` 的分支上并推送过去，日志会写明分支名。不会强推。

ssh 地址的连法和[远程主机](remote-hosts.md)一样：用网关自己的密钥（`<配置目录>/ssh/id_ed25519`）和 known_hosts（`<配置目录>/ssh/known_hosts`），
不读本机的 ssh 配置，严格校验主机密钥——先把仓库主机的公钥放进那个 known_hosts，网关自己从不学习主机密钥。
`skills:` 下的 `identityFile`、`knownHostsFile` 可以指向别处。`talkcode doctor` 会检查 git 和仓库。`/reload` 改了 `skills:`，下次拉取时生效。

网关需要 `git`（容器镜像里有）。这个版本第一次启动时，会把旧的存储整体作为一次提交搬进仓库，旧目录保留为 `skills.pre-git`。

## 常驻与库内

技能分两层，写在它自己的 frontmatter 里：

```yaml
---
name: server-ops
description: Use when operating a fleet server — SSH, EasyTier, backups.
metadata:
  talkcode-resident: "true"        # 没有这行就是库内
  talkcode-category: "运维"
  talkcode-hosts: "uniagent, awsfree2"   # 可选：只给这些主机上的智能体
  talkcode-harnesses: "claude, codex"    # 可选：只给这些 harness
---
```

- **常驻**技能会链接进每个 harness 的技能目录，每个智能体的每次请求都带着它的名字和描述。所以描述限制在
  **120 个字符**以内，写成「…时使用」；也所以只有人能把技能设为常驻：Web UI 上的 **Make resident** / **Move to library**，
  或者直接提交到仓库。智能体或复盘的 `patch` 如果改了 `talkcode-resident`，会被拒绝。
- **库内**技能是其余所有技能。它们和常驻技能一样下发到每台主机，但不链接到任何地方，所以在智能体用 `skills` 工具查到之前，
  不占任何上下文。智能体或复盘新建的技能都从这里开始。
- **分类**把技能分组；`skills` 工具的描述末尾会写每个分类有几个（`In the library: 运维 6, 开发 2, other 3.`），
  智能体正是看到这行才知道值得去库里搜一下。**主机**和 **harness**（主机是 `hosts:` 里的 id，或者 `local`；harness 是
  `claude`、`codex`、`opencode`、`agy` 或 `codebuddy`）让技能不发给用不上它、只会被误导的智能体。

值都加引号，是因为 Agent Skills 规范要求 `metadata` 是字符串到字符串的映射，按规范校验的 harness 照常列出这个技能。

## 找技能：`skills` 工具

每个智能体在 `send_file`、`schedule` 旁边都有一个 `skills` 工具（没有原生工具的智能体用 `talkcode skills search` / `show`，效果一样）：

- **search**：用几个词说需要什么，任何语言都行。最多返回五个技能，最合适的在前，得分不到最高分 40% 的不返回：名字、描述、分类、层级，以及文件在它那台机器上的位置。
  命中的是常驻技能时，会说明它已经在智能体自己的列表里。排序用 BM25，覆盖名字、描述、分类和正文，描述的权重高于正文里顺带提到的一句；
  中文按两字词匹配，所以「部署检查」能找到讲「检查部署」的技能。只搜能发给这个智能体的技能（看它的主机和 harness）。
- **show**：读一个技能：`SKILL.md` 全文，加上其他文件的清单，用 `file` 读其中一个。读一次算用一次。
  这个会话已经读过的同一版本，会只回「unchanged」而不是再给全文，直到 `/new` 或技能改了；上下文被压缩过的智能体可以加 `--again` 再读一遍。

智能体启动之后才建的技能，马上就能搜到、读到；它的文件要等那个智能体下次启动才会到那台机器上。

**搜了没找到的**就是技能库的短板。Web UI 的技能页会列出来，连同那些搜到了却没人打开的（说明描述没写清「就是它」）；
[自动复盘](#自动复盘)会拿到被复盘会话里没搜到的那些，作为该写什么技能的线索。这些记录在 `<配置目录>/skills-queries.jsonl`。

## 在 Web UI 里管理

Web UI 话题列表底部 **⚙ Menu** 里的 **Skills**。它列出所有自管技能，显示状态、是否常驻、是否钉住、分类和最后使用时间，
后面是搜了没找到的记录；点开即可编辑：

- **New**：填名字、一句用途说明和可选正文，新建技能。
- **编辑**：修改 `SKILL.md`，或 `references/`、`templates/`、`scripts/` 下的任意文件；**New file**
  可以新增一个。保存 `SKILL.md` 会带上页面读到的版本号，所以和 `patch` 一样是先读后写；被拒绝时会告诉你当前版本。
- **History**：列出改过这个技能的每次提交；**Restore this version** 就是 `revert`，这次回滚本身也会记成一次新改动。
- **Make resident** / **Move to library**：把技能放进每个智能体的列表，或者移出来；描述超过 120 个字符时，要先缩短才能设为常驻。
- **Delete** 就是 `archive`——整个技能移进 `archive/`，可以在同一页 **Restore** 回来。网关里没有任何硬删除，这个页面也没有这个操作。

它和 `talkcode skills` 用的是同一套存储和同一套规则，因为每次写入都走 `skills-store.ts`。从页面归档时，
也会像在聊天里归档一样，通知创建这个技能的那个会话。有人手工提交的改动会显示作者，同样可以恢复。

## 怎么到达智能体

每次启动智能体时，网关把在用、且发给这个智能体的技能复制到它所在机器的 `~/.talkcode/skills/<名字>/`，再把其中**常驻**的链接进这个智能体读技能的目录（库内技能只放副本，供 `skills` 工具指过去）：

| 智能体 | 它的技能目录 |
|---|---|
| Claude Code | `~/.claude/skills` |
| Codex、OpenCode | `~/.agents/skills` |
| Antigravity（agy） | `~/.gemini/config/skills` |
| CodeBuddy Code | `~/.codebuddy/skills` |

副本是只读的，所以智能体想改技能只能走 `talkcode skills`——那里有版本、能回滚——不能直接改副本，否则下次启动会被覆盖。

只会改动或删除指向 `~/.talkcode/skills` 的链接。`~/.claude/skills/<名字>` 上是真实目录、真实文件，或者你自己建的链接，就原样保留，
日志会说明这个智能体拿不到网关的副本。内容没变不重写。归档的技能，下次启动时撤掉网关的副本和所有网关建的链接；移到库内的技能，撤掉链接，保留副本。

## 什么时候算用了一次

四个信号，都来自网关已经收到的事件：

1. 智能体以 `Skill` 工具调用这个技能（Claude Code、CodeBuddy）；
2. 一条消息以 `/<名字>` 开头；
3. 任何工具调用的参数里出现 `~/.talkcode/skills/<名字>/` 下的文件——Codex、OpenCode、agy、AtomCode 都是直接读文件来用技能，读它下面的参考资料或脚本也算；
4. 智能体用 `show` 读它（`skills` 工具，或 `talkcode skills show`）——库内技能就是这样用的。

前三种在同一轮里同一个技能只算一次。`talkcode skills` 的其余操作是管理，不算使用。

## 过期与归档

网关每天检查一次智能体或复盘建的技能：**14 天**没用标为过期，**30 天**移进 `archive/`，并在该智能体下次启动时撤掉链接。
钉住的技能不受影响；人写的技能（手工提交的，或在 Web UI 页面上建的）也不受影响，因为网关看不到终端里有没有人在用。归档的技能从不删除；`restore` 一条命令就能恢复，恢复后重新计时，归档时还会通知创建它的那个会话。

在终端里直接开的会话统计不到，这是唯一的盲区。智能体写的技能如果你在意，就把它钉住，免得被自动归档。

## 任何智能体都能写

这是有意的——你说「把这个记成技能」，当场就能写——也是风险所在：自管技能会进入**所有**智能体的上下文，
一个智能体写技能，等于给其他智能体下指令。兜底是上面这些校验、改动历史和 `revert`、归档通知，以及 30 天自动归档。
访问白名单只放你信任的人；配了 `skills.repo` 的话，仓库的写权限也一样——能推这个仓库的人，同样在给所有智能体写技能。

## 自动复盘

一段对话闲下来之后，往往有值得留下的东西：漏掉的步骤、被纠正的做法、以后还用得上的技巧。在配置里指定复盘用的智能体就能打开——必须是 `agy` 智能体，一次复盘就是它所在机器上的一次 `agy -p`：

```yaml
review:
  agent: ag@uniagent             # 不写就是关闭
  model: gemini-3.8-flash-high   # 可选；不写就用这个智能体自己的模型
```

这两项也能在聊天里改（[在聊天里改配置](settings.md)）：`/setting review.agent ag@uniagent`
打开，`/setting review.agent off` 关闭，`/setting review.model` 给复盘单独指定模型。选项里只有
`agy` 智能体，因为一次复盘就是一次 `agy -p`，所有工具都被拒绝；改动在下一轮扫描开始时读取，一分钟
内生效，不用重启。

触发条件：这段对话闲置满一小时、没有正在跑的轮次，且自上次复盘以来你至少发了三条消息（定时任务和子代理的不算）。实际发生时点就是[闲置回收](chat-commands.md)停掉 agent 进程的那一刻；`/kill` 和 `/new` 之后同样等满一小时；网关重启后会补扫一遍停机期间闲下来的对话；从不被回收的会话（关闭了回收，或者会话不可恢复）在进程还在时也会复盘。定时任务、子代理和复盘自己的会话不复盘。

复盘者拿到的是：不含工具调用的这段对话（你发的每一条，再加上 agent 的回复，从新到旧填到长度上限）、技能清单（含版本号）、这段对话用到的技能全文、这段对话里 agent 自己写过的技能文件（免得刚让 agent 写好的技能又被复盘另建一份），以及[给所有智能体的指令](instructions.md)里的 `common.md`（免得把你早就定下的偏好再建议一遍）。它没有任何工具：在空的临时目录里跑，所有工具都被拒绝，读不到也改不了任何文件。它返回一段 JSON，列出要 `create`、`patch`、`write-file` 的技能及理由，外加它注意到的偏好。网关按 `talkcode skills` 的同一套规则逐条写入——`patch` 必须带上复盘时给它的版本号，不通过的丢弃并记日志。真正动文件的只有网关。

有改动时，被复盘的那个对话里会出现一行：

```text
📝 复盘：更新技能 `deploy-check`（回滚 `talkcode skills revert deploy-check c4f06d73eaad`）。偏好建议：回答先给结论
```

没改动就不发。一次只跑一个复盘，单次最多 30 分钟：模型服务排队几分钟、或者 agy 自己在重试，就等它，不半路砍掉。复盘从没见过的会话，只有最后一条消息在 24 小时内才会被看上——所以刚开启时看的是最近这一段，不会把几个月的历史翻出来；一旦有了记录（复盘过或失败过），之后由水位线和重试安排决定。失败后等六小时再试，同一批消息最多试三次；第三次仍失败就放弃，水位线推过这一批，等有三条新消息再复盘。例外是服务商对这个模型没有容量——agy 收到的回复里有 `No capacity available`，或同时出现 `UNAVAILABLE` 和 `503`——以及跑满 30 分钟上限的那种：agy 自己会一直重试 503，没有放弃上限，被杀时可能什么线索都没留下。这种不算一次尝试，一小时后再试。立刻失败的（主机不存在、spawn 失败、ssh 拒绝）到不了超时，照旧按普通失败计次。连续 12 次（约 18 小时，每次 1 小时等待加最多 30 分钟）都算没容量之后，后面的按普通失败计次，该放弃就放弃。这类会话排在正常会话后面，一轮扫描在 40 分钟后不再启动新的复盘（正在跑的那次可以再占最多 30 分钟），一串没容量的消息不会让一次扫描没完没了。没有每日上限，每个会话自己的水位线已经保证它不会被重复复盘。复盘本身记进对话库，类型是 `review`，搜索和 `list` 默认不出现。

**结果在哪里看。** 网页端的侧边面板有一个 **Reviews** 标签页：每次复盘都在这里，包括那些什么都没改、也没发过一行的。最上面的 **Suggested preferences** 汇总还没人处理的偏好建议：同样的说法只列一条，注明几次复盘提过、来自哪些对话。这些建议在任何地方都没有生效——想要的就让 agent 加进你的指令，其余的（或已经加好的）点 **Dismiss**，点过的不会再出现。一行显示被复盘的话题、时间和结果——新建或修改了技能、只有偏好建议、改动被拒、没发现什么，或者运行失败。点开可以看到每项改动和复盘者给的理由、实际有没有生效（没生效时是技能库拒绝它的原话）、偏好建议原文，以及撤销这项改动的 `talkcode skills revert` / `archive` 命令。被复盘的话题还在话题列表里时，详情里有一个按钮直接跳回去。在记录结果之前留下的旧复盘只按原始输出展示，标为 **inferred**：库里没有记过那些改动到底有没有生效。
